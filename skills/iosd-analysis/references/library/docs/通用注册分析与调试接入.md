# iosd 通用注册分析与调试接入

> 样本分析资料：保留适用版本、条件和未知项。原始捕获保留在本地；标注的历史材料路径用于定位来源。


首次学习请阅读 iosd 逆向分析教程（历史材料路径：`iosd逆向分析教程.html`） 第7、8、13至15章。本文件保留通用功能的数据模型、接口和复现说明。

分析应把“二进制中有定义”“片段已提交注册”“链接槽已存在”“片段已安装”“当前状态允许解析或执行”分别记录。VPDN 是其中一个验证案例；通用分析器按照注册 API、表达式、调用关系和状态读写建立关系，业务命令名称不参与规则匹配。

IDA attach 和 rebase 可能长时间占用界面。此时继续处理已有静态报告，暂停向 IDA 发送扫描和内存读取请求。静态分析结果保留原始采集身份，待 IDA 完成后用 RVA 对齐新的数据库地址和运行时地址。

## 分析对象与证据强度

| 对象 | 保存内容 | 结果的含义 |
|---|---|---|
| 注册 API 调用 | 调用者、调用点、参数表达式、所属条件、参数未解析原因 | 存在提交片段的调用；不直接代表成功安装 |
| 动态链接定义 | key、入口或返回 anchor、type、创建 API、创建条件 | 存在创建槽的代码；堆中是否分配成功另行核验 |
| 间接调用 | 目标表达式、getter、候选写入者、候选函数、双方条件 | 存在可能的绑定关系；不自动认定为实际目标 |
| 状态访问 | 变量身份、访问宽度、原始值表达式、读或写、上下文 | 一条命令可能影响其他路径的判断；不自动命名为 enable 或 initialized |
| 命令关联 | handler、selector 候选、原始 EOL、模式与路径示例 | 共享 handler 的 selector 分开保存；未定位 selector 时保留整组候选 |
| 未知项 | 未解析参数、目标、分支、未采集函数、循环、数量和时间上限 | 待继续分析的定义或边界，不计作不存在 |

直接调用关系、函数指针写入、变量读写分别保留。把这些关系拼接后得到触发候选，仍须核对各层条件能否同时成立。早返回、goto、消息分发和局部变量多次赋值尤其可能影响实际控制流。没有附带条件不等于已经证明无条件执行。

语法路径仅作为显示层。一个 EOL 可以有多个别名和参数形式；图、条件、注册记录与原始函数证据独立保存，避免因只显示短路径而丢失定义。隐含、未绑定或未知模式的命令仍可进入候选池。

## 通用处理流程

1. 用样本 profile 定位注册 API 和创建槽的 API。profile 保存经过消费代码确认的参数位置与布局，具体地址绑定输入身份；业务 handler 不写入通用算法。
2. 列举这些 API 的直接调用和尾跳引用，保留参数无法恢复的调用点。结合已有注册调用祖先，优先采集靠近 CLI handler 的函数。
3. 在有界批次中取得表达式、直接或间接调用、赋值、全局状态访问和所在条件。每批完成即保存检查点；未采集函数保留在待处理清单。
4. 从创建 API 参数生成动态链接候选，从注册 API 参数生成片段提交候选。表达式中的地址取不到常量时保存表达式，不丢弃调用。
5. 将函数指针槽的写入和消费建立候选关系。局部变量多次赋值保留多个可能来源，不以最后一次文本赋值覆盖所有控制流。
6. 沿直接或候选间接调用关系关联 handler 与注册事件。关联 selector、状态写入及其他函数中对同一变量的读取或判断。
7. 导出可搜索清单、完整关系、未知项和采集范围。按已知信息排序展示，不按“是否完整”删除候选。

注册顺序用依赖关系表达：创建槽、提交片段、延迟绑定、解析判断、handler 判断、消息和工作进程是不同事件。无法求出先后顺序时保存未定顺序，不强行生成启动时间线。

## 地址模型与 rebase

同一条静态证据应保留以下地址坐标：

| 坐标 | 定义 | 适用范围 |
|---|---|---|
| 采集 EA | 当时 IDB 中的地址，附采集 imagebase | 审计原始报告 |
| RVA | `采集 EA - 采集 imagebase` | 同一映像的代码、静态数据和全局槽之间的持久关联 |
| 当前 EA | `RVA + 当前 IDB imagebase` | rebase 后在 IDA 中跳转或读取 IDB |
| 运行时 VA | `RVA + 运行时 RVA 0 基址` | 读取模块内的实时对象或 core 页面 |
| 堆 VA | 运行时指针指向的地址 | 链表、回调节点、运行时模式对象等，不能直接换成 RVA |

当 IDA 已 rebase 到实际加载地址，并且数据库与进程的 RVA 0 基址相同，当前 EA 和运行时 VA 数值相同。此时不能再加一遍加载基址。每次映像重新加载、数据库 rebase、切换输入文件或切换 core，都要重新核对映射。

本样本旧报告的 imagebase 为 0，只是这次采集的属性。通用代码不把 0 当成永远成立的基址。不同构建即使有相同函数名，也不能用简单加减基址复用布局或推断二进制相同。

重定位的是有类型的地址字段。不能遍历 JSON 把所有整数统一加偏移：selector、opcode、参数范围、结构偏移和标志值都是整数，但不是地址。旧图的 `raw_hex` 也保留为旧采集字节，不通过改写原始字节伪造一次新采集。

## 调试前和 attach 期间

attach 前保留当前静态图、注册审计、候选池、样本 MD5、IDA imagebase 以及本次使用的 profile。已有文件包括 `reports/vpdn-full-graph.json`、`reports/registration-trigger-audit.json` 和 VPDN 案例目录，可作为离线分析输入，不必重新扫描一次大图。

attach/rebase 正在进行时：

- 不运行插件扫描、Hex-Rays 批量反编译、MCP 长请求或 debugger 内存遍历。
- 用离线报告分析调用图和依赖，记录后续需要采集的 RVA。
- MCP 连接超时只表示该批未取得结果，不能据此把函数或命令标为不存在。不要反复重发耗时操作。

## rebase 完成后的首次读取

1. 确认 IDA 界面恢复，目标暂停。插件的 debugger 后端要求每次读取时进程都处于暂停状态。
2. 重新运行 `dev_load.py`，释放旧界面和会话状态。旧静态结果继续作为独立文件保存。
3. 查看概览中的输入 MD5 和当前 imagebase，记录运行时映像基址。核对它们指向同一个映像的 RVA 0。
4. 切换内存源到 `debugger`，重新设置地址映射。使用没有动态修改或地址重定位影响的已知字节作为锚点，先比较一小段内存。一个锚点一致只证明该局部映射一致。
5. 先读一个模块内全局槽，再解码槽中的指针，最后读取一个动态节点。对运行时 tagged BE 指针先按相应字节序解码再去标记位，不能套用静态 IDB 的 little 布局。
6. 单节点确认后再做有数量上限、环检测和读取错误记录的链表遍历。每次采集保存数据源、映像身份、基址、时间和独立快照标识。

现有零基址静态语法 profile 会拒绝直接用于已 rebase 的 IDB；这是防止旧地址指向错误位置的检查。不要只修改 `idb_imagebase` 或删除校验来绕过它。已有报告可通过 RVA 关联；重新静态提取需要完整解析有类型的 profile 地址，并核对 rebased IDB 的指针表示。

core 的读取使用该 core 的运行时映射。未收录页面记录为缺失，禁止以 IDB 的字节或零补齐。堆对象只保存其运行时 VA，只有确认属于相应模块映射的指针才附带 RVA。

## 分阶段验收

| 阶段 | 验收标准 |
|---|---|
| 通用静态分析 | 换一组 API/profile 或合成函数仍能分析；不依赖 VPDN 名称、handler 或业务状态地址 |
| 未知分支保留 | 未解析 API 参数、间接调用、局部多来源、数量限制和采集失败都能在结果中找到 |
| 注册触发关联 | 显示直接与间接调用的依据；共享 handler 不被整体宣布为一个已确认触发命令 |
| rebase 对齐 | 同一 RVA 在旧报告、新 IDB 和运行时映射之间往返一致；不同输入身份拒绝合并 |
| 动态读取 | 先验证单槽、单节点，再验证有界遍历；来源或映射变化后不能继续使用旧验证状态 |
| 状态依赖 | 静态写读关系与运行时观察分开保存；一次快照中没有出现的定义仍留在静态候选池 |

VPDN 的完整案例继续保存在 VPDN 激活链报告（历史材料路径：`../reports/vpdn-activation-20261029/index.html`）。它用于回归检查注册、间接回调和独立状态，不作为其他业务必须遵循的状态机。

## 当前通用功能与使用方法

0.5.0 的 `lifecycle.py` 根据 API 语义配置分析注册、动态链接、函数指针绑定和全局状态写读。它不包含 VPDN handler、状态地址或命令名称。`lifecycle_api_26_01_02.json` 仅固定本样本的 API RVA、参数位置、候选置信度及运行时布局，跨构建需要重新定位和核验。

证据采集分两种来源。`ida_lifecycle.py` 是结构化 ctree 小批次采集入口；`cached_ir.py` 在 IDA 忙碌时从已有反编译文本生成启发式候选。文本导入只支持有限表达式，无法解释的原文和整个函数均保留；没有独立输入 MD5 的缓存会标记身份未验证。文本导入不把源码字符偏移伪装成指令地址，也不从非零 imagebase 下的旧自动生成名称猜地址。两种来源都不提供完整 CFG 或 selector 可行性证明。

本轮新采集取得 10,479 条直接 API 引用，结合 132 个缓存函数分析出 61 组触发关系，涉及 31 个 handler。例子包括 `segment-routing mpls`、`metadata flow` 和经过公共模式创建链的 `bulkstat` 等命令。这些是候选关系，不代表每个 selector 都会注册片段。状态分析中的变量暂不自动命名为“已启用”或“已成功初始化”。结果见 通用注册与状态依赖候选（历史材料路径：`../reports/lifecycle-candidates-20261029/index.html`）。

其中 59 个缓存函数附带匹配的输入身份，73 个缓存函数没有独立身份字段，继续作为带标记的候选。API 引用有数量上限，函数表达式也并非全部已取得。统计中的注册事件和动态链接事件是证据记录数，可能包含同一调用的引用和文本来源，不能当作唯一调用、槽或命令总数。

IDA 当前请求超时后，本轮停止派发新请求。结构化采集完成 ctree 接口兼容修正并增加表达式、指令数量和批次时间边界，但修正后的完整实机采集尚待恢复后验证。单次反编译仍可能超过批次时间；客户端超时不保证 IDA 端已停止。已提交检查点和失败记录继续保留，恢复连接前不要重发该批。

```powershell
python tools/import_cached_lifecycle.py reports/vpdn-full-graph.json --audit reports/registration-trigger-audit.json --api-capture reports/lifecycle-capture-20261029.json --output reports/lifecycle-offline-capture-20261029.json
python tools/analyze_lifecycle.py reports/lifecycle-offline-capture-20261029.json reports/vpdn-full-graph.json --syntax-paths reports/iosd-config-paths-20261029/paths.jsonl --output reports/lifecycle-candidates-20261029
```

IDA 完成 attach/rebase 并恢复后，用新的输出文件开始结构化采集。API profile 使用 RVA，所以采集端用当前 IDB imagebase 定位 API；旧语法图继续按原始身份读取并通过 RVA 关联，无需把零基址图改成新的假采集。不要对 rebase 前的采集检查点直接使用 `--resume`。

```powershell
python tools/collect_lifecycle_evidence.py http://172.16.100.165:13338/mcp reports/vpdn-full-graph.json --audit reports/registration-trigger-audit.json --output reports/lifecycle-after-rebase.json --functions 1 --batch-size 1
```

先确认这一函数成功，再在相同输入和相同 imagebase 下使用 `--resume` 继续。`--retry-errors` 会把旧失败移入 `failed_attempts`，重新排队失败函数；不会抹去旧失败证据。超时生成的 recovery 文件记录尚未确认完成的服务端键和最后已提交的检查点，客户端不自动追加清理请求。

插件内可运行 `dev_load.py`，选择 **Analyze saved registration / state evidence (RVA, no decompilation)**，依次打开采集 JSON、原始语法图 JSON 和 API profile；该菜单只分析保存的数据，不触发 Hex-Rays。查看结果时 handler RVA 按当前 imagebase 跳转，输入 MD5 不匹配时拒绝分析。

运行时可选择 **Read runtime dynamic linkage / pending bindings (verified mapping)**，使用同一个 API profile 读取动态链接表和待绑定链表。先按前面的步骤核验 debugger/core 映射。读取默认每链最多 128 条，保留原始记录、重复 key、循环、未捕获页面及数量边界；堆节点保留 VA，只有落入模块映射的字段指针才附带 RVA。profile 的 `runtime.states` 可另外列出待观察状态的 RVA、大小和字节序。

运行时读取的核心已通过合成内存测试，真实调试目标和 core 尚未验证。读取不是原子快照：每次读取检查来源和映射，debugger 后端检查暂停状态，但没有跟踪一次 resume 后再次 stop 的事件世代。读取期间应保持目标暂停；报告会明确记录这一一致性范围。输入或 imagebase 变化会使原映射验证失效。
